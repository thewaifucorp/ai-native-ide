# ide-theia-spike

Phase 1 R&D spike: a **minimal Eclipse Theia browser application** that builds,
boots, and loads a VS Code extension from **Open VSX**. Standalone app (not part
of `ai-native-ide`). "Composing applications" approach: a single `package.json`
listing Theia extensions as dependencies.

## Result (verified 2026-08-25)

- **Builds:** `theia build` → 0 errors. Bundles: `lib/frontend/bundle.js` (~28 MB),
  `lib/backend/main.js` (~17 MB).
- **Boots:** backend logs `Theia app listening on http://127.0.0.1:3010`, HTTP 200,
  full workbench renders (menu bar + activity bar + status bar).
- **Open VSX extension loaded:** SQLTools (`mtxr.sqltools` 0.28.6) downloaded from
  open-vsx.org, unpacked into `plugins/`, deployed and **activated** in the running
  IDE. Verified by (a) backend log lines from SQLTools' own activation code —
  `An authentication provider with id 'sqltools-driver-credentials' was registered`
  and `Registered object drop provider`; and (b) its **database activity-bar icon**
  plus the **"Connect" status-bar item** rendering in the browser (screenshot).

## Versions

- Node v22.22.2, npm 10.9.7, **yarn 1.22.22** (via `corepack`; npm install failed — see below)
- All `@theia/*` pinned to **1.74.1** (latest stable at time of spike)
- `react` / `react-dom` **18.3.1** (required — see "peerDependency" below)
- Extension: `mtxr.sqltools` **0.28.6** from https://open-vsx.org

## Commands

```bash
# 0) one-time: yarn (Theia's toolchain assumes it; npm install aborts here)
corepack enable && corepack prepare yarn@1.22.22 --activate

# 1) install WITHOUT lifecycle scripts (the drivelist native build fails on this
#    host and would abort the whole install — see "Known friction" #1)
yarn install --ignore-scripts

# 2) neutralise the broken drivelist native addon (re-run after every install)
yarn patch:drivelist

# 3) build the browser app (frontend esbuild + backend webpack)
yarn build

# 4) download the SQLTools .vsix from Open VSX and unpack it into ./plugins
yarn download:plugins

# 5) start the IDE
yarn start
```

`yarn start` runs:

```
VSX_REGISTRY_URL=https://open-vsx.org \
  theia start --plugins=local-dir:plugins --hostname 0.0.0.0 --port 3000
```

- **URL / port:** http://localhost:3000 by default. On the dev machine port 3000
  was already taken by another process, so the spike was verified on **3010**:
  `theia start --plugins=local-dir:plugins --hostname 127.0.0.1 --port 3010`
  → http://localhost:3010
- **Open VSX registry** is set explicitly via `VSX_REGISTRY_URL` (the
  `@theia/vsx-registry` default is also open-vsx.org). The Extensions view can
  therefore search/install from Open VSX at runtime.
- **Plugins dir:** `./plugins` (`theiaPluginsDir` + `--plugins=local-dir:plugins`).

## Known friction hit (and how it was resolved)

1. **`drivelist` native build fails / segfaults (Node 22 + spaced path).**
   `npm install` aborted on `drivelist` (`fatal error: napi.h`). Root cause: the
   project path contains a space + non-ASCII (`Área de trabalho`), and drivelist's
   `binding.gyp` uses `<!@(...)` which splits the include path on the space. No
   prebuilt binary exists for this platform (404), and a manually compiled
   `drivelist.node` **segfaults on dlopen** on this kernel. drivelist is only used
   by `@theia/core` to list physical drives — not needed for a browser IDE — so it
   is replaced with a pure-JS stub (`scripts/patch-drivelist.js`, `yarn patch:drivelist`).
   Re-run after every install (the installer re-extracts drivelist).

2. **npm vs yarn.** `npm install` did not reliably complete Theia's dependency
   graph; switched to **yarn classic 1.22.22** via corepack (Theia's supported
   package manager).

3. **`react` / `react-dom` are peerDependencies of `@theia/core` in 1.74.**
   yarn 1 does not auto-install peers, so the frontend esbuild failed with 38
   `Could not resolve 'react'` errors. Fix: declare `react`/`react-dom` `18.3.1`
   directly in this app's `dependencies`.

4. **node-pty / keytar / ripgrep** all resolved via prebuilt binaries / platform
   packages — no native compilation needed for them.

## Layout

- `package.json` — the whole app definition (Theia extensions, react, cli, scripts, `theiaPlugins`).
- `plugins/mtxr.sqltools/` — unpacked SQLTools extension (from Open VSX).
- `scripts/patch-drivelist.js` — drivelist native-addon stub.
- `src-gen/`, `lib/` — generated by `theia build` (frontend/backend bundles).
- `workspace/` — a scratch folder to open as the IDE workspace.
- `engine-sidecar/` — **Phase 2:** standalone Rust binary wrapping the real
  `ide-diff` engine (line-delimited JSON over stdio). See its `BUILD.md`.
- `engine-extension/` — **Phase 2:** local Theia extension (`link:` dependency)
  that spawns the sidecar in the backend and exposes it to the frontend over
  JSON-RPC, plus the "Engine: Diff Demo" command.

## Phase 2 — real Rust engine as a Theia backend service

Proves the round trip **frontend → Theia backend service → Rust `ide-diff`
engine → back**, de-risking porting the Bastion engines onto Theia.

- **Sidecar** `engine-sidecar/` — depends by path on the real
  `../../ai-native-ide/crates/ide-diff`; standalone crate (detached from the
  ai-native-ide Cargo workspace). Methods: `ping`, `diff`, `merge_selected`.
- **Backend service** `engine-extension/src/node/` — `EngineSidecarService`
  spawns the sidecar binary and proxies calls; bound as a Theia
  `RpcConnectionHandler` on path `/services/engine-diff`.
- **Frontend** `engine-extension/src/browser/` — a typed JSON-RPC proxy plus the
  **`Engine: Diff Demo (Rust ide-diff engine)`** command palette entry that runs
  a sample diff and shows the real engine output (message + DevTools console).

### Build & verify the round trip

```bash
# 1) TS/Theia side (no Rust needed to build/boot — the service degrades with a
#    clear "sidecar not built yet" message until the binary exists):
yarn install --ignore-scripts   # links engine-extension + typescript
yarn patch:drivelist
yarn build                       # compiles engine-extension then theia build → 0 errors

# 2) Rust side (build the real engine sidecar — see engine-sidecar/BUILD.md):
cd engine-sidecar && cargo build --release && cd ..
#   → produces engine-sidecar/target/release/engine-sidecar
#     (exactly where the backend service looks, anchored on the app cwd)

# 3) Boot and run the command:
yarn start   # then: F1 → "Engine: Diff Demo" → info toast with real hunks
```

Override the binary location with `ENGINE_SIDECAR_BIN=/path/to/engine-sidecar`.
